# Contributing

Thanks for taking a look. Issues and pull requests are welcome.

## Getting set up

```bash
git clone https://github.com/BitJacker/no-watermark
cd no-watermark
cargo test --workspace
cargo run -p nowm-gui        # the desktop app
cargo run -p nowm-cli -- scan README.md
```

Rust 1.82 or newer. The CLI builds with no system libraries; the GUI uses the
platform windowing stack at runtime. On a bare Debian or Ubuntu machine:

```bash
sudo apt-get install libxkbcommon-dev libwayland-dev libxcb1-dev
```

## Before opening a pull request

```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

CI runs exactly those three on Linux and Windows.

## Adding a character to the tables

Most contributions will be one of these. The rule is that **every entry
carries a justification**, because a cleaner that removes something legitimate
is worse than one that misses something.

- **A new suspicious codepoint** goes in `crates/nowm-core/src/chars.rs`, with
  its canonical Unicode name, a category and, where a fold makes sense, the
  replacement text.
- **A new confusable** goes in `crates/nowm-core/src/homoglyph.rs`. Do not add
  anything NFKC already folds — fullwidth forms, mathematical alphanumerics
  and Roman numerals are handled by normalisation.
- **A new carrier scheme** goes in `crates/nowm-core/src/payload.rs`, together
  with a test that encodes a known string and decodes it back.

Every change to the tables needs a test in `crates/nowm-core/src/lib.rs`. If
the character has a legitimate use in some script or context, the test must
show that use surviving.

## Adding or changing a language

All user-facing strings live in `crates/nowm-i18n/src/lib.rs` as one
`"key" => ("English", "Italiano")` line each. Nothing else in the codebase
contains prose.

To add a third language:

1. Add the variant to `Lang`, plus its `code()`, `endonym()` and `parse()`
   arm.
2. Extend the `strings!` macro to take a third literal.
3. `cargo test -p nowm-i18n` will fail until every key is translated — that is
   the point of `every_key_resolves_in_both_languages`.

Machine-translated strings are fine as a starting point if you say so in the
pull request.

## Design rules worth knowing

- `nowm-core` contains **no I/O and no prose**. It emits stable identifiers;
  the CLI and GUI translate them. Keep it that way, otherwise the JSON output
  stops being locale independent.
- The `safe` profile must never alter a visible glyph, and `scan` must never
  alter anything at all. Both are enforced by tests.
- Cleaning must stay idempotent.
- Icons are generated by `python packaging/make_icons.py`. Edit the script,
  not the PNGs; CI checks that the committed assets match the script's output.

## Reporting a bug

The most useful bug report includes the input that misbehaves. Since the
problem is usually invisible, send it through:

```bash
no-watermark reveal problem.txt
no-watermark scan --json problem.txt
```

and paste the output.
